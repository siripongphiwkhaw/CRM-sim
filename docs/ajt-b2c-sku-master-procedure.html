B2C SKU Master Control Procedure

How AJT creates, links, changes and retires B2C SKUs for its four B2C channels, who does each step, and the checks that keep every B2C sale tied to the right brand and Business Unit (BU).

1Purpose and scope

The B2C SKU master is the CRM's list of every product sold to consumers online, with its brand. Each B2C sale takes its BU from that brand, so a wrong or missing SKU record means a sale with the wrong BU or no BU.

In scope

  • B2C SKUs, e.g. TH_HYB_AJT-8850250014089, and special SKUs (_KOL, _C2, _C, _4, _PACK)
  • Channel listings in the four Phase 1 channels: D2C (AJT web shop), Shopee, Lazada, TikTok
  • Brand code on each B2C SKU, and the to-fix list for B2C

Out of scope

  • B2B products and SAP material codes (SAP master data process)
  • Prices and promotions in each channel (no B2C price list in the CRM)
  • The brand → BU list itself (changed only with AJT approval)
  • Any link between B2C SKUs and B2B products: there is none

Labels used below. System blocks the CRM refuses the data. Team checks a person checks it, using a CRM report or the to-fix list.

4Procedures

P1

New standard B2C SKU

TriggerNew product to sell online
Lead time2 working days before first listing (proposed)
FormNew B2C SKU request (8.1)
  1. E-commerceFill the request: SKU code, Thai name, brand, channels, go-live date.
  2. CDP teamCheck the code format and that the code is new; check the brand code is in the CRM brand list. Create the SKU in the CDP.
  3. CRMThe daily product feed adds the SKU and finds its brand. No brand or an unknown brand puts it on the to-fix list.
  4. CRM adminNext working day: confirm the SKU shows a brand and no to-fix item.
  5. E-commerceList the SKU in the channels (P3).

Done when the SKU is in the CRM with a brand, and no open to-fix item names it.

P2

New special SKU (KOL, promo, clearance, bundle)

TriggerCampaign, promo or clearance
Lead time2 working days before the campaign (proposed)
FormNew B2C SKU request (8.1), special part filled
  1. E-commerceRequest the SKU with base SKU, suffix, pack quantity and campaign dates. Example: base …14805, suffix _C2, pack 2.
  2. CDP teamCreate it with the suffix from section 3. Brand code may be empty.
  3. CRMLinks it to the base SKU and reads variant and pack quantity from the suffix.
  4. CRM adminCheck base SKU, variant and pack quantity against the request; correct by hand if they differ. Pack quantity must be right before the first sale.
  5. E-commerceList it in the channels (P3). After the campaign, retire it (P6).

Done when the SKU shows the right base SKU and pack quantity. A sale of 2 × _C2 then counts as 4 units.

P3

Channel listing load

TriggerListing added or changed in a channel
FrequencyWhen listings change; at least monthly per channel
InputChannel SKU export (one file per channel)
  1. E-commerceExport the SKU list from the channel: D2C web shop, Shopee, Lazada or TikTok (channel, SKU, name).
  2. IT integrationLoad it. Failed loads are fixed and reloaded the same day.
  3. CRMA listing whose SKU is a B2C SKU links itself. Any other code goes on the to-fix list as an unknown channel SKU.
  4. E-commerceFor each new to-fix listing, either fix the code in the channel or request a mapping (P4).

Done when every active listing links to a B2C SKU.

P4

Map a legacy or non-standard channel code

TriggerUnknown channel SKU on the to-fix list
Service level5 working days (proposed)
FormListing mapping sheet (8.2)
  1. E-commerceName the B2C SKU the code stands for. Example: Lazada 110010050 → TH_HYB_AJT-8850250014492.
  2. CRM adminCheck the B2C SKU exists and the names match. Map the listing by hand or by Excel upload.
  3. CRMThe next import links that channel's open orders to the SKU and gives them its brand's BU.
  4. CRM adminClose the to-fix item with the mapping reference.

Done when the listing shows "mapped by admin" and its orders have a BU. Where possible, ask the channel to move to the standard code instead.

P5

Change a B2C SKU

TriggerName, brand or pack change
ApprovalCRM admin; brand changes also the brand / BU owner
RulesSection 6
  1. E-commerceRequest the change with the reason and effective date.
  2. CRM adminCheck it against section 6. A new pack size or a different product needs a new SKU, not a change.
  3. CDP teamChange the name or brand code in the CDP; the feed carries it to the CRM.
  4. CRM adminFor a brand change, tell the brand / BU owner: sales imported after the change use the new brand's BU; past sales keep the BU saved at import.
P6

Retire a SKU or listing

TriggerProduct delisted or campaign ended
TimingWithin 5 working days of delisting (proposed)
  1. E-commerceDelist in the channel and tell the CDP team and CRM admin.
  2. CDP teamSet the SKU inactive; the CRM admin sets its listings inactive.
  3. CRMKeeps the SKU, listings and past sales. Records are never deleted, and the code is never reused.
P7

Weekly to-fix review

WhenEvery Monday (proposed)
ChairCRM master-data admin
LogTo-fix review log (8.3)
  1. CRM adminOpen the to-fix list filtered to B2C reasons, oldest first.
  2. All ownersAssign each item: unknown channel SKU → e-commerce (P4); no brand or unknown brand → CDP team (P1 step 2).
  3. CRM adminClose fixed items as resolved, or as ignored with a reason (e.g. test listing). Escalate items older than 10 working days to the e-commerce lead.
P8

Add a channel

TriggerAJT starts selling in a new shop (e.g. LINE)
RouteChange request to the CRM vendor
  1. E-commerceRaise a change request with the channel, its SKU codes and order feed.
  2. IT integrationVendor widens the channel list and sets up the feeds.
  3. E-commerceLoad its listings (P3) before its first orders.

6What may change, and how

FieldMay change?Rule
B2C SKU codeNoA new code is a new SKU (P1). The old one is retired (P6).
Product nameYesSpelling and wording only. A new size or pack is a new SKU.
Brand codeYes, with approvalSales imported after the change use the new brand's BU. Past sales keep the BU saved at import; correcting them needs the brand / BU owner's approval.
Pack quantityOnly before the first saleAfter a sale, a different pack is a new SKU, so past units stay right. Team checks (the CRM does not block this yet).
Base SKU / variantYes, by CRM adminOnly to correct a wrong automatic reading of the suffix.
Listing → B2C SKUYes, by CRM adminOnly for listings mapped by an admin. Same-code listings link themselves.
StatusYesActive ↔ inactive. Never delete.
