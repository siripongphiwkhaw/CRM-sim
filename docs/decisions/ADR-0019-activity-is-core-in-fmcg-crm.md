# ADR-0019 — Activity เป็น core model ของ CRM ตามมาตรฐาน FMCG แต่อยู่ฝั่ง B2B/SFA ไม่ใช่ B2C

**สถานะ:** Accepted — ยืนยันตัวชี้ขาดแล้ว (ยังไม่ได้ตรวจทานกับ RFP)
**จำกัดขอบเขตของ:** ADR-0007
**เกี่ยวข้อง:** ADR-0002, ADR-0006, ADR-0007, ADR-0016

## คำถาม

CRM มาตรฐานสำหรับธุรกิจ FMCG จำเป็นต้องมี Activity เป็น model หลักหรือไม่

## ข้อเท็จจริงเชิงอุตสาหกรรม

**1. ในแพ็กเกจ CRM มาตรฐาน Activity เป็น core object เสมอ**

Salesforce, Dynamics, SAP CRM, Zoho ทุกเจ้ามี Activity (Task/Event) เป็น standard
object ที่ติดมากับแพลตฟอร์ม ผูกกับ object อื่นได้แบบ polymorphic และถอดออกไม่ได้
มันเป็นโครงที่ Case, Opportunity, Lead แขวนอยู่ ไม่ใช่ของเสริม

**2. ใน FMCG ความสำคัญของ Activity ต่างกันสุดขั้วระหว่างสองฝั่ง**

| ฝั่ง | บทบาทของ Activity |
|---|---|
| **B2B / Route-to-market (SFA)** | **เป็นแกนกลางทั้งหมด** — journey plan, call card, store visit, store check, merchandising audit, การรับออร์เดอร์หน้าร้าน ตัวชี้วัดอย่าง Perfect Store และ call compliance สร้างบน visit-activity cycle ทั้งหมด ไม่มี Activity = ไม่มี SFA |
| **B2C / Consumer** | **แทบไม่ใช้** — แบรนด์ FMCG ไม่มีความสัมพันธ์รายบุคคลกับผู้บริโภค มีแต่ behavioral event ซึ่งเป็นงานของ CDP (Fabric) ไม่ใช่ Activity object ของ CRM |

## จุดที่ทำให้การตัดสินใจนี้ค้างมาตลอด

**Activity ของ CRM กับ activity ของ Loyalty เป็นคนละสิ่ง แค่ใช้คำเดียวกัน**

- **CRM Activity** — สิ่งที่พนักงานทำกับลูกค้า (โทร เยี่ยมร้าน ประชุม ติดตาม)
  เป็น object มาตรฐานของแพลตฟอร์ม ไม่มี business rule ของ Loyalty เกี่ยวข้องเลย
- **Loyalty activity** — เหตุการณ์เชิงพฤติกรรมของผู้บริโภคที่นำไปคำนวณแต้ม
  เป็น event stream คนละโครงสร้าง คนละเจ้าของ

ดังนั้น **การนิยาม Activity object ของ CRM ไม่เคยต้องรอ Loyalty confirm ตั้งแต่แรก**
สิ่งที่รอกันอยู่คือรอทีมที่ไม่เกี่ยวข้อง ตอบคำถามคนละข้อ

นี่คือปัญหาการปนกันของนิยามเดียวกับที่ ADR-0005 และ ADR-0006 ระบุไว้ แต่ตอนนั้น
ยังไม่เห็นว่ามันกำลังทำหน้าที่เป็นตัวบล็อกการตัดสินใจอยู่

## ข้อเสนอ

1. **นิยาม Activity object มาตรฐานขั้นต่ำใน Phase 1** — ลูกค้า/lead ที่อ้างถึง,
   ประเภท, เจ้าของ, เวลา, ช่องทาง, เรื่อง, ผลลัพธ์ ทั้งหมดนี้เป็นโครงมาตรฐาน
   ที่ไม่มี business rule ของ Loyalty จึงไม่ต้องรอการ confirm จากใคร
2. **ไม่ต้องเปิดใช้งานใน Phase 1 ก็ได้** ถ้ายังไม่มีผู้ใช้จริง แต่ให้มีที่ทางในโครงสร้าง
3. **ยังไม่สร้าง Loyalty activity store** — ADR-0002 ยังคงมีผลเต็มที่

## ตัวชี้ขาด — ได้คำตอบแล้ว

**คำถาม:** roadmap ของ CRM นี้จะมี field sales / SFA / เยี่ยมร้าน / route-to-market หรือไม่

**คำตอบที่ได้รับ: มี แต่ไม่ใช่ Phase 1 แน่นอน**

คำว่า "ไม่ใช่ Phase 1" คือส่วนที่ทำให้ข้อเสนอนี้หนักแน่นขึ้น ไม่ใช่เบาลง —
เพราะแปลว่า SFA จะมาถึงตอนที่ระบบวิ่งอยู่แล้วและมีข้อมูลลูกค้าจริงเต็มระบบ
การเพิ่มแกน visit เข้าไป ณ ตอนนั้นคือการรื้อ ส่วนตอนนี้เป็นช่วงเดียวที่ยังไม่มี
สิ่งใดพึ่งพา Activity อยู่เลย ซึ่งคือจังหวะที่ถูกและปลอดภัยที่สุดตามหลักของ ADR-0016

## ขอบเขตที่ทำใน Phase 1 (และที่ไม่ทำ)

**ทำ:**

- Activity object ขั้นต่ำตามมาตรฐานแพลตฟอร์ม — ลูกค้า/lead ที่อ้างถึง, ประเภท,
  เจ้าของ, เวลา, ช่องทาง, เรื่อง, ผลลัพธ์
- ความสัมพันธ์ระหว่าง Activity กับ Customer และ Lead
- ปิดไม่ให้ผู้ใช้เข้าถึงใน Phase 1

**ไม่ทำ (เป็นงานของ phase SFA):**

- journey plan, call card, store check, merchandising audit, การรับออร์เดอร์หน้าร้าน
- ตัวชี้วัดอย่าง Perfect Store หรือ call compliance
- Loyalty activity store (ADR-0002 ยังยืน)

เส้นแบ่งนี้สำคัญ เพราะทำให้ข้อเสนอเป็น *โครงสร้าง* ไม่ใช่ *feature* ซึ่งเป็นคำตอบ
ต่อข้อกังวลว่าจะเป็น scope creep ต่อ mandate "Customer Data First"

## เหตุผลเดิมของตัวชี้ขาด

- **ถ้ามี** (ซึ่งในธุรกิจ FMCG แทบจะแน่นอน) → Activity เป็น **core-structural**
  ตกอยู่ในข้อยกเว้นที่ ADR-0016 เขียนไว้เองว่า *สิ่งที่ต้องฝังในโครงสร้างแกนกลาง
  ตั้งแต่แรก การเลื่อนจะทำให้แพงขึ้น ไม่ใช่ถูกลง* — เพราะ visit object จะกลายเป็น
  แกนที่ order, audit และ KPI ทั้งหมดแขวนอยู่ การมาเพิ่มทีหลังบนระบบ always-on
  คือการรื้อ ไม่ใช่การเพิ่ม
- **ถ้าไม่มีเลย** และ CRM จำกัดอยู่แค่ customer master + ชั้นความสัมพันธ์ B2C +
  lead management → ADR-0007 ยืนได้ตามเดิม

## ผลต่อ ADR อื่น

- ถ้ารับข้อเสนอนี้ **ADR-0007 ต้องถูกจำกัดขอบเขต** — จากเดิม "ไม่มี staff activity
  ใน Phase 1 เลย" เป็น "มีโครงสร้าง Activity ตั้งแต่ Phase 1 แต่ยังไม่เปิดใช้"
- **ADR-0002 ไม่กระทบ** เพราะพูดถึง Loyalty activity store ซึ่งเป็นคนละเรื่อง
