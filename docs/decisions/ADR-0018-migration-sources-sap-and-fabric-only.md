# ADR-0018 — ต้นทาง migration มีเพียง SAP (B2B) และ CDP Fabric (B2C)

**สถานะ:** Accepted
**เกี่ยวข้อง:** ADR-0017 (migrate ทั้งหมด), ADR-0011 (CRM เป็นเจ้าของชั้นความสัมพันธ์)

## Decision

ข้อมูลที่ migrate เข้า CRM มาจากสองระบบเท่านั้น:

- **B2B → migrate จาก SAP**
- **B2C → migrate จาก CDP Fabric**

## Consequences

**ผลดีต่อ timeline (มากกว่าที่ประเมินไว้ใน ADR-0017)**

ADR-0017 เตือนว่า migration เป็นความเสี่ยง timeline อันดับหนึ่ง โดยแบ่งข้อมูลเป็น
3 กองตามความยากในการประมาณการ:

1. อยู่ในฐานข้อมูลมีโครงสร้าง เจ้าของชัด → ประมาณเวลาได้แม่น
2. Excel / ไฟล์ที่แต่ละคนเก็บเอง → กองที่กิน timeline จริง ประมาณต่ำกว่าความจริงเสมอ
3. ไม่มีในระบบใดเลย อยู่ในหัวคน → ยกไม่ได้ ต้องมีคนกรอก

**เมื่อต้นทางมีแค่ SAP กับ Fabric แปลว่าเกือบทั้งหมดอยู่ในกองที่ 1** ทั้งคู่เป็นระบบ
ที่มีโครงสร้าง มีเจ้าของ และ extract ได้ด้วยเครื่องมือมาตรฐาน ความเสี่ยงที่บันทึกไว้
ใน ADR-0017 จึงเบาลงอย่างมีนัยสำคัญ

**สิ่งที่ต้องสื่อสารกับผู้บริหารตั้งแต่ต้น**

ถ้าไม่มีระบบเดิมที่ถือ **ชั้นความสัมพันธ์** อยู่ (ผู้ติดต่อที่ sales ดูแลเอง, บันทึก
การติดต่อ, ประวัติงานบริการ) แปลว่า **ไม่มีอะไรให้ migrate เข้าชั้นที่ CRM เป็น
master ตาม ADR-0011** — ชั้นนั้นจะ **เริ่มจากศูนย์ในวัน go-live** แล้วค่อยสะสม
จากการใช้งานจริง

นี่ไม่ใช่ข้อผิดพลาด แต่เป็นสิ่งที่ต้องพูดล่วงหน้า มิฉะนั้นในวันเปิดระบบ ผู้บริหาร
จะเห็นว่า "ข้อมูลที่ CRM เป็นเจ้าของ" ยังว่างอยู่ แล้วเข้าใจว่าโครงการส่งมอบไม่ครบ
ทั้งที่มันว่างเพราะไม่เคยมีใครเก็บมาก่อน ไม่ใช่เพราะยกข้อมูลไม่สำเร็จ

**ประเด็นที่ต้องตรวจสอบ**

- **consent เดิมอยู่ที่ไหน** — ต้องยืนยันว่ามาจาก Fabric (B2C) และ SAP (B2B) ได้ครบ
  ทั้ง *สถานะ* และ *หลักฐาน* ตามที่ ADR-0017 ระบุ ถ้าฝั่งใดมีแค่ flag ยินยอม/ไม่ยินยอม
  จะได้มาแค่สถานะ ซึ่งไม่พอเมื่อถูกตรวจสอบ
- **ประวัติของชั้น identity ไม่ควรคัดลอกมาเก็บ** ตามคำเตือนใน ADR-0017 เพราะ
  เจ้าของยังเป็น SAP และ Fabric อยู่ — ยกมาเฉพาะเท่าที่จำเป็นต่อการใช้งาน
