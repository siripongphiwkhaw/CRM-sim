# ADR-0003 — ไม่คำนวณแต้มย้อนหลัง Loyalty นับแต้มจาก go-live ของตัวเอง

**สถานะ:** Accepted

## Context

ถ้าจะเก็บ activity ไว้ก่อน Loyalty go-live ต้องตอบให้ได้ก่อนว่าจะเก็บที่ความละเอียด
ระดับไหน ซึ่งมีสองระดับที่ต้นทุนต่างกันคนละโลก:

- **Analytics-grade** — ใช้ดู behavior ทำ segmentation/RFM ถ้าบางแถวหาย ซ้ำ
  หรือเวลาเพี้ยนเล็กน้อย ไม่มีใครเดือดร้อน
- **Financial-grade** — เอาไปคำนวณ **แต้มจริงที่ต้องจ่ายลูกค้า** ย้อนหลัง
  ทุกแถวต้องครบ ห้ามซ้ำ ห้ามหาย ต้อง immutable มี source_ref ตรวจย้อนได้
  และต้อง reconcile กับระบบต้นทางได้

Financial-grade ต้องมี reconciliation, idempotency key, audit trail และการทดสอบ
ระดับการเงิน — ทำเป็น "งานแถม" ไม่ได้ และจะกิน timeline ของ CRM Phase 1 โดยตรง

ความเสี่ยงเชิงองค์กรที่สำคัญกว่านั้น: ทันทีที่ผู้บริหารหรือทีม Loyalty ได้ยินว่า
"เก็บไว้ให้แล้ว เดี๋ยวคำนวณย้อนหลังได้" มันจะกลายเป็น commitment ที่ผูก
**ภาระทางการเงินจริง** อยู่บนข้อมูลที่เก็บแบบ best-effort — และถ้าข้อมูลไม่ครบ
ตอนนั้น คนที่รับผิดคือทีม CRM ไม่ใช่ทีม Loyalty

## Decision

เลือก **analytics-grade** — ไม่มีการสัญญาคำนวณแต้มย้อนหลัง
**Loyalty เริ่มนับแต้มตั้งแต่วัน go-live ของตัวเองเป็นต้นไป**

## Consequences

- ปลดภาระทางการเงิน ไม่มีแต้มค้างจ่ายจากช่วงก่อน go-live
- ตัดงาน reconciliation / idempotency / audit ระดับการเงินออกจาก Phase 1 ทั้งหมด
- ปลดแรงกดดันต่อ timeline ซึ่งเป็นข้อจำกัดจริงของ Phase 1
- ทำให้ ADR-0002 เป็นไปได้ — ถ้ายังต้องการ financial-grade อยู่ ข้อสรุปเรื่อง
  "ไม่ต้องสร้างอะไรใน CRM" จะไม่ปลอดภัยเท่านี้
- **ต้องสื่อสารให้ชัดกับธุรกิจและ marketing ล่วงหน้า** ว่าลูกค้าที่ซื้อก่อน go-live
  จะไม่ได้แต้มย้อนหลัง เพื่อไม่ให้กลายเป็นประเด็นร้องเรียนตอนเปิดระบบ
