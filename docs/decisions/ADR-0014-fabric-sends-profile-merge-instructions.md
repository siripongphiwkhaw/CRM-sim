# ADR-0014 — Fabric ส่งคำสั่งรวมโปรไฟล์มาในไฟล์ และ CRM ย้ายข้อมูลความสัมพันธ์ตาม

**สถานะ:** Accepted
**เกี่ยวข้อง:** ADR-0013 (batch รายวัน)

## Context

Fabric ทำ identity resolution เป็นงานประจำ ลูกค้าคนหนึ่งอาจมีสองโปรไฟล์
(สมัครด้วยเบอร์ครั้งหนึ่ง ด้วยอีเมลอีกครั้งหนึ่ง) แล้ววันหนึ่งถูกรวมเป็นโปรไฟล์เดียว

ปัญหาคือ CRM อาจผูกเคสงานบริการและ consent ไว้กับ id ที่กำลังถูกยุบทิ้ง
พอ batch วันถัดไปมา id นั้นไม่มีอยู่แล้ว ข้อมูลความสัมพันธ์จะกลายเป็นข้อมูลกำพร้า
ที่ไม่ผูกกับลูกค้าคนใดเลย

ความเสี่ยงที่หนักกว่าคือฝั่ง consent — การรวมโปรไฟล์อาจทำให้ **consent หายไปจาก
ลูกค้าที่ยังยินยอมอยู่ หรือทำให้คนที่ถอน consent แล้วกลับมามีสถานะยินยอมอีกครั้ง**
เพราะไปรวมกับโปรไฟล์ที่ยังยินยอม

## Decision

**Fabric ส่งคำสั่งรวมโปรไฟล์มาพร้อมกับไฟล์รายวัน** ระบุชัดว่า id เก่าตัวใดถูกยุบ
ไปรวมกับ id ใหม่ตัวใด และ CRM ย้ายข้อมูลความสัมพันธ์ตามให้อัตโนมัติ

## Consequences

- การรวมโปรไฟล์ยังเป็นการตัดสินใจของ Fabric ฝ่ายเดียว ซึ่งถูกต้องตามความเป็นเจ้าของ
  identity — CRM ไม่ต้องเดา และไม่เกิดการทำ identity resolution ซ้ำสองระบบ
  ด้วยตรรกะที่ต่างกัน ซึ่งเป็นปัญหา master control ที่แก้ยากที่สุดแบบหนึ่ง
- **ต้องยืนยันกับทีม Fabric ว่าไฟล์รายวันปัจจุบันมีข้อมูลนี้ส่งมาด้วยหรือไม่**
  ถ้ายังไม่มี ต้องขอเพิ่มตั้งแต่ตอนออกแบบ interface ไม่ใช่ไปเจอทีหลังตอนข้อมูล
  กำพร้าเริ่มโผล่ในระบบจริง
- ต้องเก็บร่องรอยว่า record ใดเคยถูกย้ายมาจาก id ใด เพื่อให้ตรวจสอบย้อนหลังได้
  เมื่อมีข้อสงสัยว่าข้อมูลของลูกค้าสองคนถูกรวมผิด
- **การรวมโปรไฟล์ที่สถานะ consent ไม่ตรงกันยังไม่มีกติกา** — บันทึกไว้เป็นคำถาม
  เปิดใน `open-questions.md` ข้อ 5
