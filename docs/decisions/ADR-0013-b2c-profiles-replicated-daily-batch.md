# ADR-0013 — CRM รับโปรไฟล์ B2C ทั้งหมดจาก Fabric ผ่าน batch file รายวัน (ข้อมูล D-1)

**สถานะ:** Accepted
**เกี่ยวข้อง:** ADR-0011 (CRM เป็นเจ้าของชั้นความสัมพันธ์), ADR-0012 (consent)

## Context

ADR-0011 ระบุว่า CRM เป็นเจ้าของชั้นความสัมพันธ์ของทั้ง B2B และ B2C แต่ identity
ของ B2C อยู่ที่ Fabric ดังนั้น CRM ต้องมี record ให้ผูกข้อมูลความสัมพันธ์เข้าไป

ทางเลือกที่พิจารณา: (a) ดึงมาทั้งหมด, (b) สร้างเมื่อมีปฏิสัมพันธ์จริง,
(c) ไม่เก็บเลย เรียกผ่าน API ตอนใช้

## Decision

**ดึงโปรไฟล์ B2C ทั้งหมดเข้ามาที่ CRM ผ่าน batch file รายวัน โดยเป็นข้อมูลของ D-1**

## Consequences

**สิ่งที่ต้องยอมรับ**

- **ข้อมูล B2C ใน CRM ช้ากว่าความจริงอย่างน้อยหนึ่งวันเสมอ** พนักงานเห็นภาพของ
  เมื่อวาน ยอมรับได้สำหรับข้อมูลโปรไฟล์ทั่วไป แต่ **ไม่พอสำหรับ consent** และ
  ไม่พอสำหรับกรณีลูกค้าโทรมาถามเรื่องรายการที่เพิ่งเกิดเมื่อเช้า
- **ยืนยันว่าความเสี่ยงเรื่อง consent lag เป็นปัญหาเชิงโครงสร้าง ไม่ใช่กรณียกเว้น**
  รอบ sync เป็นรายวันจริง ดังนั้นสถานการณ์ที่บันทึกไว้ใน `open-questions.md`
  ข้อ 1 จะเกิดขึ้นแน่นอนถ้าไม่มีมาตรการรองรับ ไม่ใช่แค่ความเป็นไปได้
- ขนาดของ CRM ผูกกับขนาดฐานลูกค้า B2C ทั้งบริษัท ไม่ใช่ปริมาณงานจริงของ CRM
  จึงต้องประเมิน sizing จากจำนวนโปรไฟล์ B2C ทั้งหมดตั้งแต่ต้น
- เกิดสำเนาโปรไฟล์ B2C ที่เก่ากว่าต้นฉบับเสมอ — ต้องระวังไม่ให้ผู้ใช้เข้าใจว่า
  ตัวเลขใน CRM คือความจริงล่าสุด โดยเฉพาะในหน้าจอที่ใช้ตัดสินใจ

**สิ่งที่ยังต้องนิยาม**

- ไฟล์รายวันเป็น **full load หรือ delta** (เฉพาะรายการที่เปลี่ยน)
- ไฟล์แสดง **การลบและการรวมโปรไฟล์** อย่างไร — Fabric ทำ identity resolution
  ดังนั้นสองโปรไฟล์อาจถูกรวมเป็นหนึ่ง แล้ว id ที่ CRM ผูกข้อมูลความสัมพันธ์ไว้
  อาจหายไป
- ทำอย่างไรเมื่อ batch ของวันหนึ่งมาไม่ครบหรือมาช้า
