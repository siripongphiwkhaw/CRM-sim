# ADR-0020 — ไม่มีการ integrate ระบบ SFA และการเยี่ยมร้านถูกบันทึกใน CRM เท่านั้น

**สถานะ:** **Withdrawn — เยี่ยมร้านถูกตัดออกจากขอบเขตทั้งหมด**
**เกี่ยวข้อง:** ADR-0006 (CRM เป็นเจ้าของ staff-generated activity), ADR-0019 (โครงสร้าง Activity ใน Phase 1)

> **ถอนแล้ว:** ภายหลังมีการตัดเรื่องการเยี่ยมร้านออกจากขอบเขตทั้งหมด ADR ฉบับนี้
> จึงไม่มีผลบังคับ เก็บไว้เป็นบันทึกว่าเคยมีข้อเท็จจริงชุดนี้อยู่ และถ้าเรื่อง
> เยี่ยมร้านกลับเข้ามาในขอบเขตอีกครั้ง ให้กลับมาอ่านฉบับนี้ก่อน
> ผลที่ตามมา: ตัวชี้ขาดของ ADR-0019 ถูกถอนไปด้วย

## ข้อเท็จจริงที่ยืนยันแล้ว

1. **ไม่มีการ integrate ระบบ SFA เข้ามาแน่นอน** — ไม่มีระบบ SFA แยกต่างหากที่จะส่ง
   ข้อมูลเข้ามาที่ CRM
2. **ฝั่ง B2B integrate ผ่าน SAP เท่านั้น**
3. **การเยี่ยมร้านจะถูกบันทึก (input) ใน CRM เท่านั้น**

## Decision

**CRM เป็นต้นทางของข้อมูลการเยี่ยมร้าน ไม่ใช่ผู้รับ** — พนักงานบันทึกเข้า CRM โดยตรง

## Consequences

**ทำให้การออกแบบง่ายลงกว่าที่เผื่อไว้**

- **ไม่มีคำถามเรื่อง integration ของ Activity เลย** ไม่ต้องออกแบบ source_ref,
  การกันข้อมูลซ้ำจากระบบต้นทาง หรือ semantics ของการ sync
- **ไม่มีความเสี่ยง master ซ้อน** เพราะ SAP ไม่ได้ถือข้อมูลการเยี่ยมร้าน และไม่มี
  ระบบอื่นถืออยู่เลย ความเป็นเจ้าของจึงชัดเจนตั้งแต่ต้นโดยไม่ต้องเจรจากับใคร
- นี่คือกรณีตัวอย่างที่ชัดที่สุดของ **ชั้นที่ 1 ใน ADR-0006** — staff-generated
  activity ที่ไม่มีระบบอื่นในองค์กรถืออยู่ ตอนนี้มี use case จริงยืนยันแล้ว
  ไม่ใช่แค่หลักการ

**ยืนยัน ADR-0019 ให้หนักแน่นขึ้น**

เมื่อ CRM เป็นทั้งที่เก็บและที่บันทึกข้อมูลการเยี่ยมร้าน Activity object จึงไม่ใช่
โครงสร้างเผื่อไว้เฉยๆ แต่เป็น**แกนที่โมดูลเยี่ยมร้านทั้งโมดูลจะสร้างอยู่บน**
การมีที่ทางไว้ตั้งแต่ Phase 1 จึงคุ้มค่าชัดเจนกว่าเดิม

**ข้อที่ต้องรู้ล่วงหน้าแม้ยังไม่ใช่ Phase 1**

การให้พนักงานบันทึกการเยี่ยมร้าน **ใน CRM เท่านั้น** หมายความว่าเมื่อถึง phase นั้น
CRM ต้องใช้งานได้จริงจากหน้าร้าน ซึ่งมีนัยที่ควรรู้ตั้งแต่ตอนนี้เพราะอาจกระทบ
การเลือกแพลตฟอร์ม:

- ต้องใช้งานบนมือถือได้จริง ไม่ใช่แค่หน้าจอ desktop ย่อส่วน
- ต้องรองรับสัญญาณขาดหาย — พนักงานขายอยู่ในร้าน ในตลาด ในพื้นที่ที่สัญญาณไม่ดี
  ถ้าบันทึกไม่ได้ตอนอยู่หน้างาน พนักงานจะไปกรอกย้อนหลังตอนกลับออฟฟิศ ซึ่งทำให้
  ข้อมูลเวลาและตำแหน่งเชื่อถือไม่ได้ และเป็นสาเหตุที่โครงการ SFA ล้มบ่อยที่สุด

**ข้อนี้ไม่ใช่งานของ Phase 1** แต่ควรถามทีมแพลตฟอร์มไว้ก่อนตัดสินใจอะไรที่ย้อนกลับยาก
