# Glossary — Customer / Activity / Loyalty

คำศัพท์ที่ใช้ร่วมกันระหว่างทีม CRM, CDP, Loyalty และ Marketing

> เหตุผลที่ต้องมี glossary นี้: คำว่า **"Activity"** ถูกใช้เรียกข้อมูลอย่างน้อยสองชนิด
> ที่ต่างกันโดยสิ้นเชิง จนทำให้การ confirm model ระหว่างทีมติดขัด ดู ADR-0005

## ความเป็นเจ้าของข้อมูล (mastership)

| คำ | ความหมาย |
|---|---|
| **Master / System of Record** | ระบบที่เป็นเจ้าของความจริงของข้อมูลชุดหนึ่ง เขียนได้ที่เดียว ที่อื่นอ่านหรือรับสำเนา |
| **B2B Master** | ปัจจุบันคือ **SAP** — ไม่อยู่ในขอบเขตของ Loyalty |
| **B2C Master** | ปัจจุบันคือ **Fabric CDP**; ตั้งแต่ **FY2028** จะเป็น **CRM** |
| **JNZ CDP module** | โมดูล CDP ที่ Fabric จะย้ายเข้ามาอยู่ภายใน CRM ใน FY2028 |
| **Master control** | การกำกับว่าข้อมูลแต่ละ field มีเจ้าของเดียว ไม่ถูกเขียนจากสองระบบพร้อมกัน |

## ข้อมูลลูกค้า

| คำ | ความหมาย |
|---|---|
| **Customer Master** | ข้อมูลตัวตนของลูกค้า (ชื่อ, ติดต่อ, consent, ประเภท) — ข้อมูลที่ *คนกรอก* และต้องมี audit trail |
| **Golden record** | ข้อมูลลูกค้าฉบับที่ถือว่าถูกต้องหลังรวมร่างจากหลาย source แล้ว |
| **Identity resolution** | การรวมข้อมูลจากหลาย source ให้รู้ว่าเป็นคนเดียวกัน — เป็นงานของ CDP |
| **Customer 360** | หน้าจอฝั่ง staff ที่รวมข้อมูลลูกค้าทุกด้านมาแสดง (เป็น *view* ไม่ใช่ master) |

## ข้อมูลกิจกรรม — สามชนิดที่ต้องไม่ปนกัน

แบ่งตาม **"ใครเป็นคนรู้ข้อมูลนั้นจริง"** ดู ADR-0006

| คำ | ความหมาย | เจ้าของ |
|---|---|---|
| **Staff-generated activity** | สิ่งที่พนักงานบันทึกเอง: การโทร, การเข้าพบ, โน้ต, การติดต่อในเคส, งานติดตาม — ไม่มีระบบอื่นถือข้อมูลนี้ | **CRM** |
| **Customer behavioral event** | เหตุการณ์ที่ลูกค้าทำในช่องทางดิจิทัล: ซื้อผ่าน D2C, ร่วมแคมเปญ, order EC mall | Fabric CDP (FY2028 → CRM) |
| **Marketing performance data** | ข้อมูลระดับรวม ไม่ผูกบุคคล | Fabric / Marketing |

| คำ | ความหมาย |
|---|---|
| **Identity-resolved activity** | เหตุการณ์ที่ผูกกับลูกค้าคนหนึ่งได้แน่นอน (ซื้อผ่าน D2C, ร่วม loyalty campaign) — ใช้กับ Loyalty ได้ อยู่ใต้ PDPA consent รายบุคคล |
| **Marketing performance data** | ข้อมูลระดับรวม ไม่ผูกบุคคล (Social engagement, Supermetrics ad metrics) — **ให้แต้มไม่ได้** ใช้ได้แค่ analytics |
| **Activity Master** | ตารางที่ระบบหนึ่ง *เป็นเจ้าของ* กิจกรรมของลูกค้า — ต่างจากการมีแค่ view ที่อ่านมาจากที่อื่น |
| **Canonical activity contract** | schema กลางที่ Loyalty อ่าน โดยไม่ผูกกับว่าใครเป็นคนป้อนข้อมูลเข้ามา (ดู ADR-0004) |

## ระดับความละเอียดของข้อมูล

| คำ | ความหมาย |
|---|---|
| **Analytics-grade** | ข้อมูลที่ผิดพลาดเล็กน้อยได้ ใช้ดู behavior / ทำ segment |
| **Financial-grade** | ข้อมูลที่ใช้คำนวณสิ่งที่ต้องจ่ายลูกค้าจริง ต้องครบ ห้ามซ้ำ immutable และ reconcile ได้ |
| **Retroactive earning** | การคำนวณแต้มย้อนหลังให้ธุรกรรมที่เกิดก่อนระบบ Loyalty เปิด — **ไม่ทำ** (ADR-0003) |
| **Source ref** | เลขอ้างอิงของรายการในระบบต้นทาง ใช้ตรวจย้อนกลับและกัน record ซ้ำ |

## Loyalty

| คำ | ความหมาย |
|---|---|
| **Loyalty ledger** | บันทึกแต้มแบบ append-only (earn / burn / adjust / expire) — ยอดคงเหลือคำนวณจาก ledger เสมอ ไม่ใช่เก็บเป็นตัวเลขนิ่ง |
| **Earn / Burn** | การได้แต้ม / การใช้แต้ม |
| **Tier** | ระดับสมาชิก คำนวณจากแต้มสะสมตลอดชีพ (lifetime) ไม่ใช่ยอดคงเหลือ |
